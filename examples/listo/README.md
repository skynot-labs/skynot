# Listo

A product spec written the way a client brings an idea to a dev shop, to try the shop on something bigger than one request: a paid todo product with brand, sync across devices, shared lists, reminders, pricing and launch. [SPEC.md](SPEC.md) has 70 requirements with ids, 8 use cases and the founder's open questions.

## Trying it

1. Commit `SPEC.md` to the root of the project's repository, so the advisors and the workers can read it.
2. In the chat, tell the Manager: *Build what `SPEC.md` describes.* Add nothing else; the point is to see what the shop does with the spec alone.
3. Read the plan it proposes before signing it.

The spec is larger than one plan can hold, so what is worth watching is how the shop handles that:

- **Coverage:** which requirement ids appear in some order's acceptance criteria, which the Manager says it left out, and which disappear without a word.
- **Who decides:** money, deleting data and anything public are the director's to decide; a technical choice (a web app or native apps, how conflicts merge) is the shop's to settle with its advisors.
- **What cannot be built yet:** a spec that needs a backend, accounts or hosting the repository does not have.
